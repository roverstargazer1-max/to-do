## 已确认的问题与修复方案

### 1. 首次启动自动制造并迁入演示数据

Computer Use 打开无痕窗口、首次访问首页，未选择演示模式就出现 Work、Personal、Side Project 和大量历史任务。独立 Chromium 复核发现，单次新 context 启动使测试数据库任务数由 6861 增至 7588，浏览器自动生成 727 条任务、751 个演示记录 ID。

按可能性检查了旧模块导入副作用、迁移误认空浏览器、测试助手注入。无初始化脚本的浏览器也复现，排除了测试助手。根因是 `mockStore` 在没有旧存储时生成演示数据，迁移 Provider 随后将这些数据写入 SQLite。

**已确认并执行的方案：** 无旧存储时只建立空内存状态，不写旧 localStorage；已有旧数据仍可读取，显式 Reset Demo 的生成能力保留。模块回归测试先失败，再通过；新增浏览器启动端到端测试。

### 2. 旧浏览器副本覆盖当前 SQLite 数据

来源独立的迁移标记不足以保护共享 SQLite：先创建 `Current local edit …`，再打开带同 ID 旧副本的新浏览器，API 中的标题实际变成 `Stale browser copy`。数据已经变化，排除了界面缓存。

**已确认并执行的方案：** 自动启动迁移传 `onlyIfEmpty`，服务端在 SQLite immediate 事务内检查迁移涉及的内容表，只有空库才导入。已有任务、Workspace 或视觉数据时跳过。手动备份恢复继续使用原有显式恢复入口。空库、已有任务、仅 Workspace 的回归先失败再通过，端到端确认当前编辑未被覆盖。

### 3. 子步骤重复出现在顶层任务列表

Computer Use 创建包含两条 Step 的任务，发现 Step 同时出现在父任务中与顶层列表。领域文档明确 Step 是平面 checklist 条目，不是独立任务。

**已确认并执行的方案：** `useTasks` 返回顶层任务；底层 API 仍提供完整记录供备份和 `useSubtasks` 使用。回归先确认父任务查询返回子记录，再验证过滤结果。端到端显式展开步骤面板，确认步骤可编辑且不出现在顶层列表。

旧端到端测试此前误把重复的顶层 Step 当成详情内容，因此未发现该问题；本轮也修正了这一错误断言。

### 4. 日历允许保存结束早于开始的事件

Computer Use 将事件改为 10 月 5 日 23:07 开始、10 月 4 日 00:07 结束，保存后重开仍是无效范围，没有错误提示。测试事件随后已改回有效范围。

**已确认并执行的方案：** 表单显示中英文错误并禁用保存；提交回调再检查；数据库仓库校验创建及日期更新，API 对无效范围返回 400。只修改开始或结束时，也与已存的另一端比较。普通事件必须有正时长，全天事件允许相同起止日期。回归先捕获倒序、零时长、无效日期及单端编辑，再验证失败请求不写入数据。

全天表单提交时把日期归一到本地午夜，避免用户不可见的旧时分使同一天的全天事件被误判为倒序。专门的组件测试先确认该边界，再验证提交的实际起止值。

### 5. 桌面日期弹窗的确认按钮落在屏幕外

针对“开始日期保存后没有改变”的候选，端到端检查在选择 Tomorrow 后无法点击 Done。截图确认弹窗越过 720px 视口底部，按钮不在可见范围；因此没有直接修改日期持久化逻辑。

**已确认并执行的方案：** 复用日期向导已有的 compact 模式，按 Popover 可用高度约束容器，使内容可滚动。修复后完整执行选择明天、Done、保存、整页刷新、重开，实际 API 和界面都保留新日期。

### 6. 备份读取失败被当作空数据

备份采集把任务、项目、习惯、专注、事件、Workspace 和节点的读取异常转换为空数组，可能生成并上传看似成功的残缺备份。部分丢失未必触发同步的数量保护。

**已确认并执行的方案：** 所有必要读取失败时让整个采集拒绝，交由现有调用方显示失败，不生成残缺结果。任务读取失败、节点读取失败和成功采集的测试先红后绿。

### 7. 通用备份恢复遗漏地点历史

地点历史被采集，但通用 SQLite 恢复成功后没有写回，只有 WebDAV 设置页自行处理；GitHub 恢复等入口因此遗漏。

**已确认并执行的方案：** 通用恢复仅在数据库恢复成功且备份提供该 section 时写回地点历史，删除设置页的重复逻辑。测试覆盖成功、恢复失败和旧备份省略字段。

### 8. Workspace 连线未进入完整备份链

代码与 ADR 0021 共同确认旧备份仅保存 Workspace 和节点，替换恢复会清除没有被归档的连线。本轮将此前记录的格式边界作为独立、完整的扩展来处理。

**已确认并执行的方案：** 为 `BackupData` 添加可选 edges section；采集、恢复、ZIP 往返、GitHub 数量保护、三方合并和冲突解析一并支持。旧归档仍可读取；它们无法凭空恢复从未保存的连线。更新 ADR 中已过时的缺口说明。兼容与关系完整性的最终回归结果见下文。

合并时省略字段表示未知，沿用基线，显式空数组仍表示删除。合并及冲突选择后的结果统一清理悬空、跨 Workspace 和重复端点连接。相关备份、ZIP、合并、数量保护的定向测试共 74 项通过。

### 9. 日程列表点击事件无法打开详情

扩大日历回归时发现 Schedule 列表的事件卡片显示点击样式，但点击后不打开详情。端到端测试先确认卡片存在且点击后没有编辑窗口；代码检查发现该视图遗漏了其他日历视图共用的事件点击回调。

**已确认并执行的方案：** Schedule 视图接入同一事件打开入口，并支持 Enter/空格键打开。事件进入事件编辑，任务进入任务详情；本轮日历端到端从 Schedule 卡片进入，再验证无效范围禁用保存、修正范围后写入 SQLite。

## 剩余边界与停止条件

视觉资产的完整主备份链需要协议和数据模型改造，不能只加一次采集调用：ZIP 使用独立二进制文件与 hash 校验；GitHub 当前直接序列化 JSON；SQLite 恢复接口接收的是旧式资产格式，不能导入版本、标注、派生结果、关系及草稿的完整模型；冲突解析的 JSON 往返会丢失 `Uint8Array`，视觉集合尚没有实体级合并和冲突处理。需要一起设计二进制编码、批量导入和合并恢复路径，本轮记录该较大改造边界。

本轮没有验证真实 GitHub/WebDAV/OAuth 账号、生产离线与 Service Worker、Electron 安装包或跨设备同步；这些没有使用测试凭据，也没有对外部账号执行写操作。旧云账号导出仍不包含 Workspace 布局；本轮补齐的是本地 Backup 和 GitHub snapshot 路径。

在上述覆盖范围内，没有剩余的已确认、可局部修复的明显问题。本轮按用户指定的“剩余问题需要较大程度重构”条件停止。
