# Kagelin Workspace 视觉对象层 — 当前 Core-Mechanism Solution

> 状态：Step 4 — Core-Mechanism Solution（已闭合，design-complete）  
> 上游权威：[`idea-definition.md`](idea-definition.md)  
> 下游当前：Step 5 — Product Design / PRD（初稿）

## 当前主方案（暂定）

使用一个资产型 `image` 节点承载视觉对象。节点只引用稳定资产 ID 和展示/语义元数据；视觉内容通过对象级、显式指定目标的 MCP 工具按需进入外部 AI 上下文；OCR、摘要、标签和区域标注作为带来源、资产版本和时间的派生信息保存；图像到流程的转换生成保留原图的待确认原生节点草稿。

端到端机制链：

```text
用户上传 / 粘贴 / 外部生成结果
        ↓
资产写入与稳定 assetId
        ↓
image 节点（位置、尺寸、角色、来源、assetId）
        ↓  外部 AI 指令或 MCP 参数明确指定 workspaceId/nodeId/resource
inspect_visual（按需取得缩略图、裁剪图或原图）
        ↓
MCP 标准结果：描述文字 + image 内容块；大对象可附 resource link
        ↓
OCR / 摘要 / 标签 / 区域标注（派生且可刷新）
        ↓
AI 操作：更新元数据、添加非破坏性标注、导入/替换资产、比较，或生成原生节点草稿
        ↓
用户确认后写入 Step / Decision / Flow；原图与 provenance 保留
```

### 外部 AI 的实际读写契约

Skill 或工具描述只负责指导调用时机；真正的视觉数据面是 MCP 工具实现和
资产读取服务。外部客户端通过标准 MCP 工具发现和调用，不需要硬编码
Kagelin 的画布选择状态。

建议的读取契约如下：

```text
inspect_visual({ workspaceId, nodeId, representation, purpose })
  → descriptor + derived context + optional image content
```

`get_workspace_blueprint` 只返回图片节点的轻量描述，不返回整个 Workspace
的原图。`inspect_visual` 在服务端完成归属校验后，才读取指定资产，并根据
`representation` 返回缩略图、裁剪区域或原图。为保证视觉模型能立即使用，
小型或按需裁剪的结果优先以内嵌 `image` 内容返回；较大的原图可以附带受权
限保护的 Resource link，但不能假设每个客户端都会自动读取该 link。

建议的写入契约分为三种：

- `patch_workspace` 或 `update_visual`：修改节点元数据、布局和非破坏性标注；
- `import_visual`：从受控的 URL、授权本地文件或外部资产句柄导入二进制，
  再创建或替换 image 节点；
- 图像到流程：只生成待确认的 Step/Decision/Flow 草稿，确认后才进入原生
  Workspace 语义。

MCP 没有通用的“读取当前对话附件”约定，因此不能承诺外部 AI 刚生成的图片
会自动进入 Kagelin。导入必须有 MCP 能够解析的 URL、文件路径或资产句柄；
否则由用户在 Kagelin 中粘贴/拖放，AI 再通过节点 ID 操作它。

## 参考机制的采用边界

[tldraw AI integrations](https://tldraw.dev/docs/ai) 提供了“视觉资产 + 结构化画布对象”双表示的局部机制参考；本方案采用其双表示思想，适配为 Kagelin 的 Workspace 节点与 AI 合约，不直接复制其 SDK 或画布实现。视觉模型对形式化结构转换的不稳定性仍是外部风险，见 [`idea-definition.md`](idea-definition.md) 的证据段落。

## Guest 与外部 MCP 的边界

云端注册用户的基本链路是：

```text
外部 AI → MCP Server → 云端资产 Adapter → 视觉资产
```

Guest 的 Workspace 数据在浏览器 IndexedDB，独立运行的 MCP 进程不能直接
读取它。若要保持已确认的 Guest/云端/Backup 全链路，必须增加 Kagelin
侧的 Guest asset bridge：浏览器页面主动连接本地 MCP 进程，使用一次性配对令牌
转发读写请求，桥接再调用 Guest 存储。这个增加的是 Kagelin 的连接层，
不是 Codex 或 Claude 的改造。

桥接不可用时的合法降级是：提示用户打开 Kagelin 或把图片显式上传/同步到
可访问的资产位置；不能假装 MCP 已经读到了 Guest 原图。

## 当前外部未知与风险

- 视觉模型对小字、精确几何、复杂流程和表格的识别质量尚未在 Kagelin 场景验证；当前降级是保留原图并展示不确定性。
- 图片资产的大小、数量、同步和 Backup 成本尚未测量；当前承诺是通过配额、降级和明确失败反馈控制，不承诺无限资产。
- Guest 浏览器桥接的连接生命周期、配对、权限撤销和浏览器关闭行为可能影响离线恢复、跨设备和分享；需要 Guest 与云端共享同一资产语义，并允许桥接不可用时明确降级。
- 外部客户端或模型可能只消费文本而不消费 MCP image 内容；必须保留 OCR/摘要/尺寸等文本降级，但不能把降级结果宣称为等价的视觉理解。
- 外部 AI 生成结果不一定具有可供 MCP 解析的资产句柄；首发不能把“自动捕获所有对话生图结果”作为承诺。
- 恶意 SVG、外部 URL、隐私图片和 AI 生成内容的来源/权限需要进入 Step 5 的生产行为设计。

## Step 4 机制决策

- **S4-Q1 — AI 视觉检查的内容传输与派生缓存方式：采用推荐方案。** 默认只返回图片描述和派生信息；外部 AI 明确指定目标后，按需返回限制尺寸的缩略图/裁剪图/原图。OCR、摘要、标签和区域标注可以缓存，但必须带资产版本、生成时间和来源，资产变化后失效或标记过期。
- **MCP 读写边界：采用标准工具结果承载视觉内容。** `inspect_visual` 负责模型主动读取；图片以内嵌 `image` 内容块为主要视觉输入，大对象可使用受权限保护的 Resource link。`import_visual` 只接受服务端可验证的 URL、授权文件或资产句柄。
- **Guest 访问边界：采用浏览器桥接作为必要机制。** 这是对已确认的 Guest 全链路承诺的技术展开；如果未来取消桥接，必须同步撤回“外置 AI 可直接访问 Guest 本地资产”的承诺，而不能用 Skill 文字补齐。

## Step 4 闭合与消费审查

- 必要机制已覆盖：独立资产、显式目标、按需图片传输、派生缓存、非破坏性写入、Guest 可达性、结构化转换和非执行关系。
- 主方案已唯一化：标准 MCP 工具作为外部 AI 的控制面，资产服务作为视觉数据面，云端 Adapter 与 Guest 浏览器桥接作为两种可替换的存储可达性路径。
- 关键不变量已明确：节点不存二进制；原图不被静默覆盖；默认不读取整个 Workspace；关系不产生执行语义；权限校验不由 Skill 替代。
- 证据状态：机制依据 MCP 标准能力与当前代码边界；Kagelin 图片场景的性能、客户端兼容性和视觉理解质量尚未实测，仍属于 Step 5 的风险与验证输入。
- Step 5 可直接消费：创建图片节点、外部 AI 按需查看、AI 元数据/标注写入、资产导入/替换、转换确认、Guest asset bridge 不可用降级和 Backup 资产恢复。
