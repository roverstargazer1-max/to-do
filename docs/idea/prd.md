# Kagelin Workspace 视觉对象层 — PRD（初稿）

> 当前步骤：Step 5 — Product Design  
> 当前成熟度：Core-validation prototype 设计中  
> 设计状态：active  
> 证据状态：not-built（尚未完成视觉闭环验证）  
> 上游权威：[`idea-definition.md`](idea-definition.md)、[`core-implementation-solution.md`](core-implementation-solution.md)

本文是第一版可持续维护的产品需求文档，不代表生产架构已经完成，也不代表
视觉理解质量已经验证。后续行为设计、验证结果和用户确认都应继续修改这份
文档，而不是另建互相竞争的 PRD。

## Problem Statement

AI 自动生成 Workspace 时，容易把截图、草图、空间关系和视觉证据压缩成大段
文字。文字适合表达步骤和判断，却不能完整表达界面状态、几何布局、视觉层级
和不确定的观察结果。当前 Workspace 没有一个稳定承载图片、让外部 AI 按需读取
并能安全写回结果的对象。

外部 Codex、Claude Code 等 AI 客户端不会共享 Kagelin 画布的 UI 选择状态；它们
只能通过已经支持的 MCP 工具与 Kagelin 协作。因此需求必须建立在稳定的
Workspace/Node/Asset 标识和标准 MCP 内容传输上，而不是“选中画布后 AI 就能看到”。

## Solution

增加一个资产型 `image` 节点，保存截图、参考图、草图、SVG 或外部生成结果的
视觉上下文。图片本身作为独立的 Visual asset 持久化，节点保存稳定资产引用以及
标题、角色、来源、尺寸和派生信息。

图片不是可执行步骤，也不替代 Step、Decision 或原生流程连线。AI 可以在外部
指令或 MCP 参数明确指定目标后按需检查图片，可以生成 OCR、摘要、标签、区域
标注和结构化草稿；原图必须保留，结构化草稿只有在用户确认后才成为原生流程
对象。

不修改 Codex、Claude Code 等客户端的业务代码。Kagelin 通过标准 MCP 工具发现、
权限校验、读取资产并返回标准 image 内容块；Skill 只负责调用编排和使用说明。

## Product principles

1. **结构和视觉并存**：Step/Decision 表达流程事实，Image node 表达观察、证据和参考。
2. **资产与节点解耦**：同一图片可以被多个节点复用，节点不保存二进制内容。
3. **显式目标、按需读取**：默认只暴露轻量描述；原图必须由外部请求明确指定目标后读取。
4. **原图优先保真**：AI 的识别、标注和转换都是派生或草稿，不能静默覆盖来源。
5. **非破坏性写入优先**：元数据、标注和版本替换优先于直接修改原始像素。
6. **关系不自动执行**：视觉关系帮助人和 AI 理解上下文，不产生调度或运行时语义。
7. **降级必须诚实**：客户端不支持视觉输入、桥接不可用或分析失败时，明确报告限制，不能伪装成已读取。

## User Stories

1. 作为需要整理资料的用户，我希望把图片、截图或草图放入 Workspace，以便在流程旁保留视觉事实。
2. 作为用户，我希望图片节点可以移动、缩放、命名和归类，以便把视觉资料组织到合适的流程区域。
3. 作为用户，我希望同一个图片资产可以被多个图片节点引用，以便避免重复上传并保留一致来源。
4. 作为使用外部 AI 的用户，我希望通过 Workspace ID、节点 ID 或明确的资源描述让 AI 查看指定图片，以便不依赖画布 UI 选择。
5. 作为用户，我希望 AI 默认只看到图片描述和必要元数据，以便控制隐私、上下文长度和读取成本。
6. 作为用户，我希望 AI 在我明确要求时查看原图、缩略图或某个区域，以便针对性分析而不是扫描整个 Workspace。
7. 作为用户，我希望 AI 能在图片上产生 OCR、摘要、标签或区域标注，以便后续搜索、讨论和追溯。
8. 作为用户，我希望 AI 能修改图片节点的标题、说明、角色和标注，以便维护视觉上下文而不破坏原图。
9. 作为用户，我希望 AI 能导入一个可验证的图片资源或替换为新版本，以便把外部生成结果纳入 Workspace。
10. 作为用户，我希望 AI 把图片转换成 Step、Decision 或 Flow 草稿，并在写入前看到待确认内容，以便利用结构化流程能力又不丢失原始证据。
11. 作为用户，我希望图片与 Step/Decision 之间可以表达 supports、evidence-for、reference 或 derived-from，以便 AI 理解图片和流程的关系。
12. 作为 Guest，我希望图片与 Workspace 一样保存在本地并可进入 Backup，以便保持本地优先和数据可携带性。
13. 作为注册用户，我希望图片资产随云端 Workspace 持久化，以便在允许的设备和 AI 连接中复用。
14. 作为用户，我希望图片读取、导入、替换和删除都有明确的失败提示，以便知道 AI 实际完成了什么。
15. 作为维护者，我希望图片资产不会因为删除一个节点而被错误删除，也不会留下不可回收的孤儿数据，以便资产生命周期可管理。

## Product behavior slices

### B1. 创建图片节点

触发：用户上传、拖放、粘贴截图，或使用外部 AI 导入一个可验证资源。

行为：系统先创建或确认独立 Visual asset，再创建引用该资产的 image node。节点
拥有标题、角色、来源、尺寸和展示配置；原始文件不进入节点 JSON。

成功反馈：图片能在画布中渲染，节点和资产都有稳定标识，刷新后仍可读取。

失败路径：格式、大小、配额、病毒/脚本风险或来源不可访问时拒绝写入，并说明
失败原因；不得留下已宣称成功但无法恢复的半成品。

### B2. 画布展示与基础操作

图片节点支持移动、缩放、标题/说明编辑、替换、复制引用和删除节点。删除节点
不等于删除资产；只有没有引用且经过回收策略确认的资产才可进入回收流程。

首发以资产展示为主，不提供完整逐笔 Sketch 编辑器。裁剪、标注和覆盖层属于
后续行为设计，不能改变原始资产。

### B3. 外部 AI 按需读取

触发：外部 AI 指令或 MCP 参数明确提供 `workspaceId`、`nodeId`、资产标识或
可解析资源；如果描述对应多个对象，AI 必须请求澄清。

行为：

1. AI 先读取 Workspace 的轻量语义快照和图片节点描述；
2. AI 调用对象级视觉检查工具；
3. 服务端校验 Account、Workspace、节点和资产归属；
4. 仅读取请求的缩略图、裁剪区域或原图；
5. 返回文字元数据、已有派生信息以及标准 MCP image 内容；必要时附受保护的资源链接。

默认行为：不读取整个 Workspace 的原图，不因画布中存在图片就自动把图片加入上下文。

降级行为：客户端或模型不支持视觉内容时，返回 OCR、摘要、尺寸和“未完成视觉
检查”的明确状态；文本降级不宣称等价于原图理解。

### B4. AI 非破坏性写入

AI 可以通过 Workspace 写入入口修改图片节点的元数据、关系和结构化标注。标注
包括框选区域、箭头、文字说明或 OCR 区域，但属于覆盖层/派生信息，不改变原始
图片字节。

所有写入都需要当前版本或等价的并发校验，返回操作回执和新版本信息。权限、
确认和 Domain Command 规则不能由 Skill 文案替代。

### B5. AI 导入、替换和转换

导入必须提供 MCP 服务能够验证的 URL、授权本地文件或资产句柄。不能假定外部
AI 对话中的附件或生成图片会自动传给 Kagelin。

替换默认创建新资产版本并保留旧版本/来源关系；高影响替换、删除或批量变化需要
用户确认。图像转流程只产生待确认的 Step、Decision、Flow 草稿；确认后才写入
原生流程语义，原图和 provenance 始终保留。

### B6. 视觉关系

图片可以与 Step、Decision、Doc 或其他图片建立 typed relation，例如：

- `reference`：图片是参考资料；
- `supports`：图片支持某个流程对象；
- `evidence-for`：图片是某个状态或判断的证据；
- `derived-from`：图片或结构化结果源自另一个对象。

这些关系是上下文语义，不是现有 visual-only Connection 的运行时替代品，不触发
任务、调度或自动化。

### B7. Guest、云端和 Backup

云端用户的外部 AI 读取路径为外部 AI → MCP Server → 云端资产存储。

Guest 的图片位于浏览器本地存储，独立 MCP 进程不能直接读取浏览器 IndexedDB。
要保持 Guest 全链路能力，Kagelin 需要提供配对的本地浏览器桥接：浏览器页面
主动连接本地 MCP 进程；Guest asset bridge 转发 MCP 读写请求，页面使用 Guest 存储完成操作。

桥接不可用时，工具必须明确返回“本地应用未连接”，不能返回伪造图片。用户可以
打开 Kagelin、在 UI 中完成操作，或显式把资产转移到可访问位置。

Backup 必须同时包含 Workspace/节点元数据、资产 manifest 和资产文件；Restore
必须恢复引用关系、来源和派生信息的一致状态，并继续遵守现有 Backup 的确认和
覆盖语义。

## AI/MCP requirements

1. MCP 服务必须通过标准工具发现机制提供视觉能力，不依赖客户端硬编码 Kagelin 节点类型。
2. `get_workspace_blueprint` 只返回图片节点描述，不默认返回原图或大段 base64。
3. `inspect_visual` 是模型可主动调用的对象级工具，至少支持节点/资产目标、目的、表示形式和并发版本。
4. 视觉结果优先返回标准 `image` 内容块；大对象可以附带受权限保护的 Resource link，但不能依赖客户端必然自动读取资源链接。
5. `import_visual` 必须限制来源类型、大小、MIME、访问范围和外部抓取风险；禁止把任意 URL 抓取作为无约束能力。
6. 节点变更、标注、关系和流程草稿必须使用统一的 Workspace 写入漏斗，不能为 MCP 建立绕过正常写入政策的第二条路径。
7. MCP 服务必须返回可机器读取的状态、版本、来源和错误分类，便于 AI 在下一步继续或停止。
8. Skill 只描述路由、时机和确认规则；实际权限、资产读取、写入和回执由 MCP/应用服务执行。
9. 不支持视觉输入的外部客户端可以使用文字派生信息降级，但必须标明结果不是原图视觉判断。

## Persistence and data requirements

### Visual asset

独立保存原始二进制和必要元数据：稳定资产标识、所有者、MIME、大小、尺寸、
哈希、来源、创建时间、版本和生命周期状态。节点不得保存图片 base64，也不得
只保存无法恢复的临时 URL。

### Image node

保存资产引用、标题、角色、来源说明、展示配置、当前资产版本和派生信息索引。
图片节点仍是 Workspace 节点，不复制 Task、Habit、Project 等领域实体。

### Derived visual information

OCR、摘要、标签、区域和置信度必须指向资产版本、生成来源和生成时间。源资产
变化后派生内容必须失效或标记过期，不能继续伪装成当前原图事实。

### Version and deletion

原始资产默认不可变；替换产生新版本或新资产。删除节点不自动删除共享资产；
资产回收必须有可追踪引用检查、宽限期和失败恢复路径。

## Privacy, safety and reliability

- 所有 MCP 读取和写入都必须经过 Account/Workspace/Node/Asset 归属校验。
- 资产链接不得默认公开；临时读取地址必须受权限、时效和范围约束。
- 外部 URL 导入必须防止 SSRF、重定向绕过、超大响应和伪造 MIME。
- SVG 若支持，必须经过脚本和危险内容清理；无法安全清理时拒绝渲染或导入。
- 读取和分析必须有大小、像素、并发和速率上限，超过限制时提供缩略图、裁剪或文本降级。
- 图片可能包含个人信息、凭据和第三方版权内容；产品需要在上传、外部 AI 读取和分享处给出清晰的范围提示。
- Guest asset bridge 只绑定本机回环地址，使用可撤销的配对凭据，并按 Workspace/资产再次校验，不能成为任意本地文件服务。
- 网络、存储、桥接或视觉模型失败时保留原图和已有节点状态，返回明确的未完成结果。

## Initial acceptance criteria

以下是初稿级验收，不代表最终数值承诺：

- [ ] 用户可以通过上传、拖放或粘贴创建可渲染的 image node。
- [ ] 刷新、重新打开和合法 Backup Restore 后，图片节点仍能通过稳定资产引用恢复。
- [ ] Workspace 轻量快照不包含默认原图；外部 AI 必须明确指定目标后才能请求图片内容。
- [ ] MCP 工具能够返回标准 image 内容；不支持视觉内容时能诚实降级为派生文本并标明限制。
- [ ] 外部 AI 可以更新标题、说明、关系或非破坏性标注，并获得可追踪回执。
- [ ] 原图不会因 AI 分析、转换、替换或删除节点而静默丢失。
- [ ] 图像转流程只产生待确认草稿，确认前不会生成原生执行性流程事实。
- [ ] Guest asset bridge 未连接时不会泄露或伪造本地图片；连接后只允许授权 Workspace/资产访问。
- [ ] 删除共享节点不会误删仍被引用的资产；无引用资产进入可恢复的回收路径。
- [ ] 恶意或不支持的图片格式会在写入/渲染前失败，并提供可理解反馈。

## Scope

### Included in the initial product direction

- 一个统一的 `image` 节点，而不是 Screenshot、Sketch、GeneratedImage 等多个节点类型；
- 图片、截图、草图、外部生成结果的统一资产引用；
- 画布展示、移动、缩放、标题和基础元数据；
- 外部 AI 的明确目标、按需读取、标准图片返回和文本降级；
- OCR、摘要、标签、区域标注等可追溯派生信息；
- 非破坏性 AI 写入、资产版本替换和待确认的结构化转换；
- 非执行性视觉关系；
- Guest、云端、Backup 的一致数据责任，以及 Guest 浏览器桥接前提。

### Out of scope for this initial draft

- 完整逐笔可编辑的白板/Sketch 编辑器；
- 自动理解整个 Workspace 的所有图片；
- 由某一个特定生图模型提供图片节点的前提能力；
- 将图片节点直接变成任务执行器、调度器或自动化触发器；
- 自动捕获所有 Codex/Claude 对话中的生成图片；
- 不受限制的任意 URL 抓取、任意本地文件读取或公开图片链接；
- 最终配额数值、部署拓扑、监控方案和实施任务拆分。
